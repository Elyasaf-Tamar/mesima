## עדכון כמה מכשירים מסונכרנים

סנכרון 4.9.2 שומר חותמות שינוי נפרדות גם לפריטים, שדות בתוך פריטים, שיוכים וסדר. כך שני מכשירים יכולים לסמן פריטים שונים באותה רשימה בלי שסימון אחד ימחק את האחר.

פורמט הסנכרון מתקדם לגרסה 2. היישום החדש קורא וממיר מסמכי סנכרון מגרסה 1. יישום 4.9.1 דוחה מסמך בגרסה 2 לפני שיוכל להעלות מעליו גרסת רשימות ישנה. המידע המקומי במכשיר הישן נשמר, אך הסנכרון שלו ייעצר עד העדכון.

סדר עבודה מומלץ:

1. שמור גיבוי JSON בכל מכשיר שיש בו שינויים שטרם הסתנכרנו.
2. פרסם את כללי Firestore ו־Storage המעודכנים בפרויקט Firebase המתאים, לאחר בדיקתם.
3. עדכן את כל מכשירי Windows ואת קוד הווב של מכשירי Android לפני חידוש עבודה מקבילה. לסנכרון שינויים שהמתינו במכשיר ישן, פתח את היישום המעודכן באותו פרופיל נתונים.
4. התקן מעטפת Android 1.8.2 כדי לקבל את תיקוני הרקע: חידוש תזכורות, כתיבה בטוחה של עדכון, טיפול בהרשאות וגיבוי פעולות מהמכשיר.
5. בדוק במכשירים המעודכנים שינוי בשני פריטים שונים, סנכרון, סגירה ופתיחה מחדש.

ה־HTML שומר מסלולי תאימות למעטפות Android קודמות. עדכון HTML לבדו אינו מתקין קוד Kotlin חדש. חידוש תזכורות ללא WebView ושאר תיקוני המעטפת דורשים APK 1.8.2.

אין למחוק נתוני יישום או להחליף פרופיל דפדפן כחלק מהעדכון. כדי להתקין APK מעל התקנה קיימת נדרשים אותו applicationId ואותו מפתח חתימה. APK פיתוח אינו תחליף לחבילת ההפצה החתומה.

## פיתוח ובדיקות

דרושים Node 22.12 ומעלה, Python 3, ולבדיקות Android ו־Firebase גם JDK 17 מלא. לבניית Android דרושים Gradle 8.9 ו־Android SDK עם `platforms;android-35` ו־`build-tools;35.0.0`; Gradle עשוי להתקין גם רכיבי SDK הנדרשים על ידי Android Gradle Plugin.

```sh
npm ci
npm run build
npm test
npm run test:archive
npx playwright install chromium
npm run test:ui
npm run test:rules
```

בלינוקס נקי אפשר להתקין את ספריות המערכת של הדפדפן באמצעות `npx playwright install --with-deps chromium`. ניתן להפנות לדפדפן בדיקה מותקן בעזרת `MESIMA_CHROME`, או לחבילת Playwright מותקנת בעזרת `MESIMA_PLAYWRIGHT` המצביע לקובץ `index.mjs` שלה.

`npm run test:ui` מריץ את תרחישי הממשק והעברות הסנכרון בפרופילים מבודדים. הוא אינו מפעיל את `live-sync-diagnostic.cjs` או בדיקות המחייבות חשבון אמיתי. `ui-46-test.mjs` נשמר כבדיקה היסטורית של ממשק קודם ואינו חלק משער האימות הנוכחי.

`npm run test:rules` מפעיל אמולטורים של Firestore ו־Storage בפרויקט `demo-mesima`. הבדיקות בודקות גיבויים מגרסאות ישנות וחדשות, הפרדת חשבונות, איסור דריסה, מגבלות גודל ונתיבי סנכרון.

## בניית Android

לאחר `npm run build`:

```sh
cd android
gradle testDebugUnitTest assembleDebug --no-daemon
cd ..
python3 tools/verify-apk-version.py android/app/build/outputs/apk/debug/app-debug.apk
```

ב־Windows אפשר להשתמש ב־`tools/setup-android.ps1` ולאחריו `tools/build-android.ps1`. שני הכלים משתמשים באותה תיקיית כלים משותפת: `../.mesima-build-tools/android`. משתנה `MESIMA_TOOLS_DIR` מחליף את תיקיית הכלים המשותפת שמעל `android`.

בנייה מקומית פועלת גם ללא `android/app/google-services.json`. כדי להפעיל Firebase צריך לספק את תצורת הפרויקט המקומית המתאימה לפני הבנייה. הקובץ אינו נכלל ב־Git או בארכיון הציבורי.

## בניית Windows

```sh
npm ci --prefix desktop
node desktop/build.cjs
```

ב־Windows מריצים לאחר הבנייה `npm run test:desktop` כדי לבדוק את החבילה בפרופיל בדיקה מבודד, לרבות שמירה והפעלה מחדש. הבדיקה מתאימה גם לחבילה מקומית בלי Firebase.

הפלט נמצא ב־`desktop/dist/Mesima-win32-x64`. לבניית חבילת Windows עם מטא־נתונים של קובץ ההפעלה, השתמש ב־Windows או בסביבת בנייה שתומכת בכלי Windows של Electron Packager.

אפשר לבדוק הכנת נכסים ותצורה בלי לארוז את Electron:

```sh
node desktop/build.cjs --prepare-only
```

קובץ Firebase אינו תנאי להפעלה מקומית. אם אין תצורה, היישום עולה במצב מקומי ומדווח שהענן אינו מוגדר. אם יש `android/app/google-services.json`, הבונה מפיק ממנו את תצורת Windows. אפשר גם לספק קובץ חיצוני באמצעות `MESIMA_GOOGLE_SERVICES`, או קובץ עם `project`, `bucket`, `apiKey` באמצעות `MESIMA_FIREBASE_CONFIG`.

היישום שומר נתונים מקומיים בפרופיל Mesima. החלפת חבילת התוכנה אינה מחייבת מחיקת הפרופיל. התזכורות של Windows דורשות שתהליך Mesima יישאר פועל, לרבות כשהחלון מוסתר במגש המערכת. סגירה מלאה של התהליך או כיבוי המחשב מפסיקים אותו.

## תזכורות, הרשאות וגיבויים

Android שומר כעת כללי חזרה ואירועים, ומחשב מהם תזכורות מחדש אחרי יקיצות, תזכורות, שינוי שעה ואתחול. התור מוגבל ל־100 מועדי יקיצה קרובים; תזכורות באותו מועד משויכות לאותה יקיצה, ואחרי טיפול בתור הוא מתמלא שוב. זו מגבלת רישום זמני במערכת ההפעלה, ולא מחיקה של יתר כללי החזרה.

הפעלה בפועל עדיין תלויה בהרשאות התראות, הרשאת תזכורות מדויקות ובהתנהגות החיסכון בסוללה של Android. אבחון מדווח על בקשה שנמסרה למערכת, חסימה או שגיאה; הוא אינו מבטיח שהמשתמש ראה או שמע את ההתראה. לא מוצגת עוד הבטחה להשתלטות במסך מלא שאינה ממומשת.

ייבוא, ייצוא וגיבוי במעטפות משתמשים בגבול אחיד של 20 MiB, לפי בתים ב־UTF-8. פעולות שהושלמו דרך התראות או וידג׳טים נכללות בגיבוי גם אם קוד הווב טרם הספיק לקלוט אותן; שחזור הפעולות שומר את יום הביצוע ומונע רישום כפול.

קובצי JSON כוללים את תוכן האפליקציה, ואינם כספת מוצפנת מקצה לקצה. יש לשמור עותקי גיבוי במקום המתאים לתוכן שבהם.
