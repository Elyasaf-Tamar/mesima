# חיבור Firebase למשימה 4.5 — מדריך שלב אחר שלב

נבדק מול התיעוד הרשמי ב־6 בספטמבר 2026. שמות תפריטים עשויים להשתנות מעט לפי שפת הקונסול.

הקוד כבר הוכן בגרסה 4.5. אתה מגדיר את הפרויקט בחשבון Google שלך; לאחר מכן אני יכול לחבר את קובץ ההגדרה ולבנות APK חדש עם מפתח החתימה הקיים.

החיבור הקיים הוא **גיבוי ושחזור בענן באפליקציית Android**. קובץ הגיבוי מכיל את הנתונים והתמונות המשובצות. הוא אינו מבצע סנכרון שוטף בין מכשירים, והגיבוי התקופתי לתיקיית הטלפון הוא יכולת נפרדת.

## 1. צור פרויקט

1. פתח במחשב את [Firebase Console](https://console.firebase.google.com/).
2. היכנס לחשבון Google שבו תרצה לנהל את האפליקציה.
3. בחר **Create a project / Add project**.
4. תן שם, למשל **Mesima**. זה שם תצוגה לבחירתך.
5. רשום בצד את **Project ID** שהמערכת מציעה. הוא יכול להיות שונה מהשם, וצריך להיות ייחודי.
6. אם מוצעות תוספות Google Analytics או Gemini, אפשר להמשיך בלעדיהן לצורך החיבור שבנינו.
7. סיים עם **Create project**, ואז **Continue**.

סימן שסיימת: מוצג מסך **Project overview** של הפרויקט. [הוראות יצירת פרויקט ורישום Android](https://firebase.google.com/docs/android/setup).

## 2. הכן חיוב והתראות תקציב

Cloud Storage דורש כיום תוכנית **Blaze**, המחוברת לחשבון חיוב. קיימות מכסות ללא עלות, אבל אין הבטחה שהשימוש שלך יהיה חינמי. [דרישת Firebase הרשמית](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024).

1. בפרויקט לחץ **Upgrade**, או פתח את אזור **Usage and billing**.
2. בחר **Blaze — Pay as you go**.
3. קרא את התנאים והשלם קישור לחשבון חיוב רק אם אתה מסכים לכך. את פרטי האשראי מזינים אצל Google, לא בצ׳אט.
4. פתח את חשבון החיוב ב־Google Cloud, ומשם **Budgets & alerts → Create budget**.
5. בחר תקציב שמסונן לפרויקט Mesima, סכום חודשי שנוח לך לעקוב אחריו, והתראות למשל ב־50%, 90% ו־100%.
6. בדוק שכתובת קבלת ההתראות היא כתובת שאתה קורא.

**התראת תקציב אינה מגבלת חיוב קשיחה ואינה עוצרת לבדה את Firestore או Storage.** אם אינך רוצה לקשר חשבון חיוב, אפשר להמשיך להשתמש בגיבוי המקומי; חיבור הענן הנוכחי ימתין. [ניהול תקציב והתראות](https://firebase.google.com/docs/projects/billing/avoid-surprise-bills).

## 3. הפעל כניסה לחשבון

1. בתפריט הפרויקט פתח **Authentication**. אם אינך רואה אותו, חפש בתפריט המוצרים או בקטגוריית Build.
2. לחץ **Get started**.
3. פתח **Sign-in method** או **Sign-in providers**.
4. בחר **Email/Password**.
5. הפעל את אפשרות **Email/Password** הרגילה ושמור עם **Save**. את Email link אפשר להשאיר כבוי.

סימן שסיימת: Email/Password מופיע כ־**Enabled**. את חשבון המשתמש של האפליקציה ניצור אחר כך מתוך משימה; הוא נפרד מהחשבון שמנהל את Firebase. [הוראות Authentication](https://firebase.google.com/docs/auth/android/password-auth).

## 4. צור את מסד Firestore

1. פתח **Firestore Database → Create database**.
2. אם נשאלת על מהדורה, בחר **Standard**; אם נשאלת על מצב, בחר **Native mode**.
3. אם מוצג Database ID, השאר **(default)**. הקוד שלנו משתמש במסד ברירת המחדל.
4. בחר אזור אחסון מתאים. לשימוש שלך בישראל אפשר לבחור **Tel Aviv — me-west1**, אם מוצע בקונסול. זו הצעה למיקום, לא הבטחה למחיר הנמוך ביותר. מיקום Firestore אינו ניתן לשינוי לאחר יצירת המסד. [מיקומי Firestore](https://firebase.google.com/docs/firestore/locations).
5. במסך כללי הגישה ההתחלתיים בחר **Production mode**.
6. לחץ **Create / Enable** והמתן להשלמה.

השלב הבא יאפשר גישה לחשבונות האפליקציה באמצעות הכללים שהכנתי. אין צורך ליצור ידנית אוספים או מסמכים: הגיבוי הראשון ייצור אותם. [הקמת Firestore](https://firebase.google.com/docs/firestore/quickstart).

## 5. פרסם את כללי Firestore

1. בתוך Firestore פתח את לשונית **Rules**.
2. במחשב פתח את הקובץ `firestore.rules` שבתיקיית המדריך הזה, בעורך טקסט.
3. העתק את כל התוכן, החל מ־`rules_version` ועד הסוגר האחרון.
4. החלף בתוכן הזה את כל הטקסט שבעורך Rules של Firestore.
5. לחץ **Publish**, וודא שאין שגיאת תחביר ושאין שינויים שממתינים לפרסום.

הכללים נותנים למשתמש גישה לגיבויים שלו בלבד. צריך להעתיק את הקובץ המלא, ולא להוסיף אותו מתחת לכלל קיים שפותח גישה לכולם. זהו קובץ Firestore; ל־Storage יש קובץ אחר. [פרסום כללי Firebase](https://firebase.google.com/docs/rules/manage-deploy).

## 6. צור Storage ופרסם את כלליו

1. פתח **Storage**, בדרך כלל תחת **Databases & Storage** או Build.
2. לחץ **Get started**. אם מופיעה בקשת שדרוג ל־Blaze, חזור לשלב 2.
3. צור את **דלי ברירת המחדל** ובחר אזור. אם אותו אזור שבחרת ל־Firestore מוצע גם כאן, אפשר לבחור בו לשמירת השירותים באותו אזור.
4. אם מוצעת בחירת כללים התחלתית, בחר **Production mode**.
5. סיים את ההקמה. במסך **Files** אמור להופיע שם הדלי.
6. פתח את לשונית **Rules** של Storage.
7. פתח במחשב את `storage.rules` שבתיקיית המדריך, והעתק את כל תוכנו.
8. החלף את כל תוכן עורך הכללים של Storage ולחץ **Publish**.

בגרסה שלנו Storage שומר את קובץ הגיבוי השלם, כולל התמונות שבתוכו. Firestore שומר את רשימת הגיבויים ואת הפרטים עליהם. אין צורך להעלות ידנית תמונות או ליצור תיקיות בקונסול. [הקמת Storage](https://firebase.google.com/docs/storage/android/start).

## 7. רשום את אפליקציית Android והורד את ההגדרה

1. חזור ל־**Project overview** ולחץ על סמל Android או **Add app → Android**.
2. בשדה **Android package name** כתוב בדיוק: `il.mesima.app`.
3. בשדה **App nickname** אפשר לכתוב **Mesima Android**. אם מוצע SHA-1, אין צורך בו עבור כניסת הדוא״ל והסיסמה שהכנו.
4. לחץ **Register app** ואז **Download google-services.json**.
5. שלבי הוספת SDK שמופיעים באשף כבר מיושמים בקוד שלנו; אין צורך להעתיק שוב קטעי Gradle.

אם כבר רשמת את האפליקציה, פתח **Project settings → General → Your apps**, בחר את אפליקציית Android והורד משם את הקובץ מחדש. [רישום האפליקציה והורדת ההגדרה](https://firebase.google.com/docs/android/setup).

**מורידים את הקובץ לאחר יצירת Storage**, כדי שיכלול את שם דלי ברירת המחדל. אם הורדת אותו קודם, הורד עותק מעודכן. [דרישת ההגדרה של Storage](https://firebase.google.com/docs/storage/android/start).

## 8. שמור את הקובץ כדי שאחבר אותו לאפליקציה

העתק את הקובץ אל:

```text
C:\Users\HEAVY\Desktop\Personal Project\App Version 4.5\android\app\google-services.json
```

שם הקובץ חייב להיות בדיוק `google-services.json`, ללא `(1)` או סיומת `.txt`. אפשר גם לצרף כאן את הקובץ. אין צורך לשלוח סיסמת Google, סיסמת משתמש באפליקציה, פרטי אשראי או קובץ Service Account.

כתוב לי: **„סיימתי את הגדרות Firebase ושמרתי את הקובץ; מזהה הפרויקט שלי הוא …”** וציין אם שני קובצי הכללים פורסמו.

מכאן אוכל לבדוק התאמה בין קובץ ההגדרה, מזהה החבילה ושם הדלי; לבנות APK חדש עם אותה חתימה; ולתת לך קובץ להתקנה. ה־APK הקודם נבנה ללא פרויקט Firebase, ולכן העתקת הקובץ לתיקייה או עדכון HTML בלבד לא יפעילו בו את החיבור.

## 9. התקן ובדוק גיבוי אמיתי

את השלב הזה עושים **אחרי שאספק APK שנבנה עם ההגדרה שלך**.

1. באפליקציה הקיימת ייצא גיבוי ידני ושמור אותו לפני בדיקת העדכון.
2. התקן את ה־APK החדש כעדכון לאפליקציה הקיימת. אם מתקבלת שגיאת התקנה, עצור ושלח לי את נוסחה; אל תסיר את האפליקציה הישנה כדי לעקוף אותה.
3. פתח **⋯ → הגדרות → גיבויים וארכיון**.
4. באזור **גיבוי בענן · Firebase** לחץ **כניסה / יצירת חשבון**.
5. הזן כתובת דוא״ל וסיסמה לחשבון האפליקציה ולחץ **צור חשבון**. זה אינו דורש שימוש בסיסמת Google שלך.
6. הוסף משימת ניסיון, למשל „בדיקת Firebase”, וצרף תמונת ניסיון.
7. לחץ **גבה עכשיו לענן** והמתן להודעה **„הגיבוי נשמר בענן”**.
8. בקונסול בדוק שב־Authentication מופיע המשתמש, ב־Storage נוצר קובץ תחת `users/<uid>/backups/`, וב־Firestore נוצר מסמך תחת `users/<uid>/backups/<id>`.

## 10. בדוק שחזור

1. ודא שיש לך גיבוי ידני עדכני. שחזור מחליף את כל המידע המקומי במידע שבגיבוי שבחרת.
2. מיד אחרי גיבוי הניסיון שנה רק את שם משימת הניסיון. הימנע משינויים אחרים לפני הבדיקה.
3. לחץ **בחר גיבוי לשחזור**, ובחר את הגיבוי לפי תאריך ושעה.
4. לאחר ההורדה תופיע בקשת אישור. אפשר לבחור **ביטול** כדי לוודא שהמידע המקומי נשאר כפי שהוא.
5. פתח שוב את הגיבוי ובחר **שחזר** רק אם אתה רוצה להחזיר את כל המידע למצבו בזמן הגיבוי.
6. ודא שמשימת הניסיון חזרה לשם הקודם, שהתמונה קיימת ושאפשר לפתוח את התוכן.
